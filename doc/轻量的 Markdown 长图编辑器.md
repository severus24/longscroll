# 轻量的 Markdown 长图编辑器

我认为这个想法很值得做，而且它的使用场景非常明确：把 AI 对话、Markdown 文档转换成适合手机阅读和分享的长图，让接收者不需要下载文件、不需要打开 Markdown 阅读器，直接在微信、QQ 等聊天窗口里就能预览和阅读。

我建议不要把它做成一个简单的 Markdown 转图片工具，而是做成一个轻量的 Markdown 长图编辑器（Markdown to Long Image），核心体验是编辑、预览、导出三步完成。

## 二、我建议的功能设计

### 1. 内容输入

支持三种输入方式：

- 直接编辑：提供 Markdown 编辑器，可以直接粘贴 AI 对话结果。
- 上传文件：支持 `.md` 文件，上传后自动解析。
- 粘贴内容：支持直接粘贴 ChatGPT、Claude、Gemini 等 AI 对话生成的文本。

这里建议保留原始 Markdown，不要因为调整排版而修改原文。

### 2. 实时渲染预览

这是整个网页最重要的部分。

桌面端采用左右分栏布局：

| 左侧编辑区    | 右侧预览区   |
| ------------- | ------------ |
| Markdown 源码 | 实际阅读效果 |
| 支持编辑      | 实时更新     |
| 支持上传文件  | 支持滚动预览 |
| 支持快捷键    | 模拟手机屏幕 |

移动端则切换成编辑和预览两个 Tab，避免空间不足。

预览区需要支持：

- 标题：H1、H2、H3。
- 正文：段落、粗体、斜体、删除线。
- 列表：有序列表、无序列表。
- 引用：引用块、提示块。
- 代码：代码块、行内代码。
- 表格：完整表格渲染。
- 图片：本地图片和网络图片。
- 分割线：章节分隔。

另外，建议加入目录、标题间距、段落间距等排版控制。

### 3. 手机模拟与长图导出

这里是我认为最值得重点设计的功能。

建议默认使用 iPhone 16 Pro 的模拟参数：

| 参数                | 设置                 |
| ------------------- | -------------------- |
| 设备                | iPhone 16 Pro        |
| CSS 视口宽度        | 402 px               |
| CSS 视口高度        | 874 px               |
| Device Scale Factor | 3                    |
| 导出图片宽度        | 1206 px              |
| 导出格式            | PNG / JPEG           |
| 导出高度            | 根据文章内容自动决定 |

你提出的 HTTP User-Agent 也可以实现，例如使用 iPhone 16 Pro 对应的 Safari User-Agent。

但这里有一个技术细节需要注意：

User-Agent 不等于真实 iPhone 渲染环境。

User-Agent 主要影响服务器识别设备、浏览器识别和部分页面适配逻辑，而实际渲染效果还取决于浏览器内核、视口尺寸、设备像素比等参数。

因此，我建议导出时使用 Playwright：

1. 创建一个模拟 iPhone 16 Pro 的浏览器上下文。
2. 设置 iPhone Safari User-Agent。
3. 设置 402 × 874 的视口和 3 倍设备像素比。
4. 加载已经排版好的 HTML。
5. 等待字体、图片和页面内容加载完成。
6. 使用 Full Page Screenshot 截取整个页面。
7. 输出高清 PNG 图片。

如果只是模拟 iPhone 的 UA 和尺寸，使用 Chromium 就可以；如果以后追求真正的 iOS Safari 渲染一致性，则需要进一步使用真实 iOS Safari 环境验证。

## 五、技术实现方案

我建议第一版采用简单、低维护的架构，不需要数据库，也不需要用户登录。

| 模块            | 推荐技术      | 作用                   |
| --------------- | ------------- | ---------------------- |
| 前端            | React + Vite  | 网页界面               |
| Markdown 编辑器 | CodeMirror 6  | 源码编辑               |
| Markdown 解析   | markdown-it   | 内容解析               |
| 安全处理        | DOMPurify     | 防止 HTML 注入         |
| 样式            | CSS           | 排版和主题             |
| 截图            | Playwright    | 模拟 iPhone 并导出长图 |
| 后端            | Node.js       | 接收导出任务           |
| 图片处理        | Sharp（可选） | 图片压缩和尺寸处理     |

### 推荐的数据流程

![image-20261103160722090](/Users/zhanghao/Library/Application Support/typora-user-images/image-20261103160722090.png)

有两个技术问题建议从一开始就考虑：

1. 超长图片的处理：Chromium 对单张超长截图存在尺寸限制，文章特别长时应该支持分段截图后拼接，避免导出失败。
2. 字体与图片加载：导出之前必须等待字体和图片加载完成，否则容易出现文字错位、图片空白以及排版高度不准确的问题。

## 七、正式开发前，我想确认一个关键问题

你提到的 iPhone 16 Pro User-Agent，我理解是希望最终图片尽可能接近别人用 iPhone 打开文章时看到的真实页面，而不是单纯把 Markdown 渲染成一张固定宽度的图片。

这里有两种实现方向：

1. 你希望最终采用哪种渲染方式？

- 两种模式都支持

  > - 使用 iPhone 16 Pro 的 UA、视口、DPR 和移动端页面样式，模拟手机实际阅读效果，再截取长图。
  >
  > - 不需要模拟浏览器，只按照 1206px 图片宽度进行排版和导出，控制更简单。

可以在真实设备模拟和固定尺寸长图之间切换。

2. 你准备把网页部署在哪里？

- 本地优先，后续可以部署到服务器
